# ADR-0001: Technology Stack & Decoupled GPU Renderer Architecture

**Status:** Accepted  
**Date:** 2026-08-11  
**Deciders:** Lead Architect, Graphics Engineer, Desktop Application Engineer  

---

## 1. Context & Problem Statement

LUMORA is a professional projection mapping and show control application designed for live visual performances, installations, festivals, stage shows, and building projection. 

Live performances demand:
- Ultra-low latency and steady 60 FPS output.
- Multi-monitor output routing (editor controls on primary screen, clean fullscreen output without cursor or UI artifacts on projectors).
- Complex perspective mapping, 4-point corner pinning, and non-linear GPU mesh warping.
- High stability (zero crashes during a live show, emergency blackout, automatic crash recovery).

We need to choose an optimal architecture that provides reliable desktop integration, multi-monitor window routing, hardware-accelerated video decoding, fast UI iteration, and strict separation between UI reactiveness and GPU frame rendering.

---

## 2. Considered Options

1. **Native C++ / OpenGL / Vulkan + Qt**: Extremely high performance, but long development iteration cycle and cross-platform UI builder complexities.
2. **Rust + wgpu + Tauri**: High memory safety and graphics control, but limited native multi-window IPC flexibility for independent off-screen video streams across displays.
3. **Electron + React + TypeScript + WebGL 2.0 / WebGPU Renderer Engine**: Best balance of rapid UI development, robust multi-display management (`BrowserWindow` per projector output), access to native file system APIs for native `.lumora` archives, and GPU hardware acceleration.

---

## 3. Decision

We choose **Electron + React 18 + TypeScript + Vite + WebGL 2.0 Graphics Renderer**.

### Key Architectural Requirements:

1. **Decoupled Renderer Pipeline:**  
   React is **NEVER** involved in frame-by-frame rendering loops. The WebGL rendering loop runs in an independent render loop (`requestAnimationFrame` / `OffscreenCanvas` / WebGL context) consuming an immutable or ref-based frame payload from state.

2. **Multi-Window Display Architecture:**  
   - **Editor Window:** Contains UI controls, canvas viewports, inspector, media browser, and show controls.
   - **Projector Output Window(s):** Borderless, fullscreen, no cursor, no chrome windows rendered directly on secondary displays (Display 2, Display 3, etc.).
   - Communication is handled over high-speed IPC (Inter-Process Communication) and shared off-screen texture buffers or canvas mirror streams.

3. **GPU Projection Mapping:**  
   Perspective mapping is performed via 3x3 Homography Matrices computed from four corner pin control points and applied directly inside WebGL vertex/fragment shaders. Mesh warping uses GPU vertex buffers calculated from mesh grid coordinate interpolation.

4. **Native Container `.lumora`:**  
   Projects are saved as compressed `.lumora` archives containing JSON manifests, project state files (`surfaces.json`, `scenes.json`, `effects.json`, `calibration.json`), and bundled media files with SHA-256 checksums.

---

## 4. Consequences

### Positive:
- Cross-platform desktop capabilities (Windows, macOS, Linux).
- Multi-display window positioning and fullscreen control out-of-the-box.
- WebGL 2.0 provides 60 FPS GPU-accelerated surface rendering, blend modes, and shader effects.
- Fast, responsive React dark theme UI.

### Negative / Mitigations:
- Electron bundle size: Mitigated by stripping unnecessary modules and optimizing asset bundles.
- Garbage collection pauses: Mitigated by pre-allocating WebGL buffers, matrices, and reusing texture arrays rather than allocating objects inside render loops.
